# 输出格式与可读性规范

目标：深度不等于难读。机构研报的可读性来自**结论前置、信息分层、数字规范、视觉锚点**。专题和完整报告撰写前读取本文件。直接回答默认聊天内交付，只适用语言、来源和数字规范。

## 1. 按深度组织正文

专题分析使用结论、关键依据、涉及的假设/估值、反证和待验证事项，不规定章节数。完整研究使用以下头部三件套；只有明确深研才要求九章。

依次为：结论框 → Tearsheet → 预期差 Gap 表。读者 60 秒内应获得完整决策信息。

**报告语言**：默认使用用户请求语言；若用户未明确，用当前对话中用户与 Agent 的常用沟通语言。用户显式指定语言时优先遵守。标题、章节名、缺失数据标记、事实/判断标记、免责声明和图表说明必须统一语言；英文报告使用 `My view` / `Not obtained` / `Sources and timestamps` 等等价标记。

**结论框**（引用块，放标题之后第一屏）：

> **内在价值判断：低估**｜**未来 1–3 个月市场交易方向：偏上**｜**投资动作：分批买入**
> （估值标签由标定规则产出｜财报可信度 A｜置信度 中高）
> 一句话论点：市场把 X 定价成 Y，但证据 Z 显示……
> 综合估值区间 $L–$H（现价 $P，隐含空间 +a% ~ +b%）｜上行证伪：……｜下行证伪：……

**Tearsheet**（一页速览表）：现价/市值/52周区间/关键倍数/护城河/财报可信度/催化剂 Top1/上行证伪 Top1/下行证伪 Top1，每行带来源+时间戳。

**方向纪律**：内在价值判断回答"值多少钱"，市场交易方向回答"接下来 1–3 个月市场最可能先交易哪个变量"，投资动作回答"在当前赔率和不确定性下怎么做"。三者可以不同，但不能混写成一句结论。

英文报告可用等价头部：

> **Intrinsic value view: Undervalued** | **1-3 month market trading direction: Upward bias** | **Action: Accumulate in tranches**
> (Valuation label from the calibration rule | Earnings credibility A | Confidence: Medium-high)
> One-sentence thesis: The market prices X as Y, but evidence Z suggests...
> Fair value range $L-$H (current price $P, implied upside +a% to +b%) | Upside invalidation: ... | Downside invalidation: ...

## 2. 章节写法

- 每章第一行：**「本章要点：」+ ≤2 句结论**。先给答案再给论证，读者可只读要点扫完全文。
- 英文报告每章第一行使用 **"Key takeaways:"**；中文报告使用 **"本章要点："**。
- 段落 ≤5 行；超过就拆或改表格。连续 3 段没有数字的分析要警惕——多半是空话。
- "事实"与"我的判断"用标记显式分离；判断句给出依据编号或数据。
- 图表就近原则：表格紧跟引用它的论述，不集中堆在章末。

## 3. 数字规范

- 千分位分隔；货币符号 + 单位一次性声明（"以下未注明均为 $B"）；百分比保留 1 位小数，估值每股保留整数或 1 位。
- **精度匹配不确定性**：DCF 输出写 "$185–$240" 而不是 "$212.47"——假装精确是伪严谨。
- 同比/环比用 +/− 号；负数不用括号（中文语境）。
- 每张表格列出"来源/时间"列或表注。

## 4. 视觉件（文本渲染，Markdown 内直接可读）

**Football field 估值图**（使用多方法时可选，仅画实际方法；反向 DCF 是诊断，不参与价值加权）：

```text
反向DCF(证伪)      │────市场隐含────│
情景加权DCF            ▓▓▓▓▓▓▓▓▓ 170———225
三要素/EPV          ▓▓▓▓▓▓ 150———195
相对估值               ▓▓▓▓▓▓▓▓ 165———215
EVA/剩余收益          ▓▓▓▓▓▓▓ 160———205
综合区间 [L———————H]        现价 P ▼
```

用等宽代码块 + ▓/─ 字符按比例画；现价用 ▼ 标注。若输出 .docx/.xlsx，可改用真实图表。

**敏感性热力标注**：3×3 表中对高于现价的单元格加粗，让"什么假设下现价合理"一眼可见。

**桥式表**（收入桥/公允价值变动桥）：起点 → 各驱动分项(+/−) → 终点，一行一driver。

## 5. 交付物清单

**原则：直接回答在聊天内交付；专题和完整研究默认交付 Markdown 报告**；一切中间产物（JSON、脚本输出、CSV）为内部留档，不进入交付清单。

| 产物 | 角色 | 说明 |
|---|---|---|
| 专题或完整报告 **.md** | **交付物（默认）** | 按实际问题深度组织；只有完整研究使用九章 |
| 报告 .pdf / .docx / .xlsx workbook | 交付物（用户指明时） | 使用相应技能转换与验版；工作簿仅包含本次实际模型和来源 |
| Tearsheet | 完整报告内嵌 | 不强制专题或直接回答提供 |
| 估值假设 JSON | 内部留档 | dcf.py config，留在工作目录供复算；关键假设以摘要写入报告附录 |
| 检查器输出 | 内部留档 | 结果摘要写入报告附录 |
| 财务 CSV / 脚本原始输出 | 内部留档 | 用户索要时才提供 |

## 6. 长度与密度纪律

- 深度 = 信息密度 × 覆盖完整性，不是字数。每章自查："删掉哪一段读者不受损失？"能删就删。
- 不规定最低字数或表格数量。专题以回答问题为止；完整报告覆盖九章但不以篇幅作为质量指标。
- 附录收纳原始数据长表；正文只放被论证使用的数字。

## 7. 置信度自评（完整报告附；专题说明关键限制）

| 维度 | 评分（高/中/低） | 说明 |
|---|---|---|
| 数据完整度 | | 关键数据获取比例、Tier 1 覆盖率 |
| 假设稳健性 | | 关键驱动、恢复/增长条件与敏感性 |
| 证据独立性 | | 来源是否独立、模型是否共享同一盈利假设 |
| 预期差清晰度 | | variant view 是否可证伪 |
| 财报可信度 | A/B/C/D | forensic 模块输出 |
| **综合置信度** | | 低置信度 + 好标签 ≠ 大仓位 |

## 8. 预测可追踪性

- 每条核心预测使用区间和明确验证日期，不使用“长期向好”之类无法到期判定的句子。
- 经营 KPI、催化剂路径、估值倍数与股价/总回报分开记录；股价方向错误不自动等于经营判断错误，反之亦然。
- 更新报告时保留旧预测和原时间戳，只追加实际结果、命中状态、误差归因和模型回写。
- 命中状态只使用：命中、部分命中、未命中、无法验证；“无法验证”必须解释缺失数据或事件延期。
- 英文报告使用 `Forecast register`、`Validation date`、`Hit / Partial hit / Miss / Not verifiable` 等价字段。
